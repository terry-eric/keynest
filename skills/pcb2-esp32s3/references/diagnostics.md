# 診斷與證據

## 麥克風：人聲小、只聽到吹氣

已知結果來自 `hardware/evidence/populated-hardware.json`、驗證摘要及歷史測量，不等於這次連接的板子已通過。

- 使用者確認 U10 是 ZTS6672；歷史設計是 ICS-43434、pin 2 接地。取得的 ZTS6672 DS-13 表格與本板左右 slot 實測不一致；不能單憑料號或表格強制切到 right。
- right 曾連續 40 個視窗全零；診斷版各 20 個視窗確認 right 全零、left 非零。先讀 `/api/state` 的 `mic_slot`、`mic_slots`，錄音停止後才切換比較，測試後恢復有資料的聲道。
- gain 8、20.032 秒 WAV 曾沒有 dropped 或削波；安靜與提示說話區間的 250 ms AC RMS 中位數約 −66.77／−66.98 dBFS，未見明顯人聲反應。這是未通過結果，不是把增益提高即可解決的證據。

測試時區分三件事：

1. 傳輸正常：有效 PCM、frame 計數增加、CRC 正確、age ≤1 秒、沒有 dropped。
2. 聲學反應：指定安靜與說話／測試音時段，確認 AC RMS、峰值與 WAV 回應；不能用直流偏移當作聲音。
3. 主觀可聽性：核對使用者聽的是下載 WAV、板上喇叭還是其他播放來源。

`mic_slots` 是增益前 48 kHz DMA block 的 PCM24 統計；網頁即時 meter 是 16 kHz 增益後 PCM16、扣除視窗平均值的 AC 音量，兩者不能直接比較。波形「自動放大」只改畫面；WAV 保留原始偏移，數位 gain 會同時放大聲音與噪聲，並可能削波。dBFS 不是 dB SPL。

若只有吹氣有聲，將強烈孔口低頻壓力擾動與人聲收音分開判斷。優先查實際貫穿收音孔、孔位、焊錫／污染／外殼遮擋，再查 SELECT／CONFIG、供電、I²S WS／BCLK／資料對齊，必要時評估麥克風損傷。這是候選原因，沒有檢查前不能確診。

保存快照中的 Multi-Layer 圓形 FILL 不等於製造鑽孔；沒有 HOLE record 也不足以證明實板沒有孔。需要 PCB 正反面近照、製造 drill／route 檔或實板檢查。檢查現行電路／布局時可使用可用的 EasyEDA review skill 與連線；沒有連線時註明資料來源，避免修改或宣稱核對最新實板。

## USB／Web 離線或錯誤

- 先用串列埠 inventory 分辨未連接、ROM PID 1001、埠被占用或多個 PID 4005 裝置；`127.0.0.1:8028` 是這台電腦的 proxy，不代表 PCB 已連接。
- 若畫面選項改了但實板狀態未變，核對瀏覽器錯誤、proxy route、USB endpoint 與 firmware 版本，不能只看 DOM 值宣稱操作成功。
- app.js／proxy 更新後，確認執行中的服務是否仍載入舊 Python 模組。重啟前保存未下載 WAV；不要先重載頁面清掉錄音。
- v7 音效上傳曾有 CRC 異常，有限重送是已採用的緩解措施，根因尚未定位。保持完整 CRC 校驗，不移除檢查來讓上傳「成功」。

## SD 異常

使用者曾回報卡座方向問題；後續 v7 曾讀到約 7.95 GB 的 8 GB FAT32 卡並成功錄音／重複下載，但也讀成約 32 MB、FATFS 掛載失敗或 CID CRC 錯誤。400 kHz 降速尚未證明修復。

先確認這次卡座、接線、供電、卡片與實際容量／CID／CSD，再使用現有唯讀診斷。容量／CRC 不穩時不要格式化、重建分割表或假設只是 FAT 損毀。繼續提供 Flash／browser 替代方式，SD 音效持久保存仍需實機驗證。

維護 `firmware/keyboard/VALIDATION.md` 的公開摘要，完整原始測量保留本機。記錄版本、測試方法、frame／CRC／dropped、使用的聲道及結果限制。新證據可以修正上述基準，但不要把某次測試結果擴大成所有硬體版本的結論。
